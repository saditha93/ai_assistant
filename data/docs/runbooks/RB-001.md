## Purpose
This runbook covers the response to degraded availability or elevated error rates on the CrestPay API gateway or payment orchestrator, regardless of root cause. It complements the more specific runbooks RB-002 (database connection pool), RB-003 (TLS certificate), and RB-004 (card switch failover).

## Detection
Primary signals are the gateway 5xx error rate dashboard and the payment-orchestrator authorisation success rate metric, both alerting when success rate drops below 95% for more than 3 minutes. See ARCH-001 for the full request flow these metrics cover.

## Steps
1. Acknowledge the page and check the incident dashboard for automatically correlated signals: database pool utilisation, NorthGate latency, certificate expiry countdown, and recent deployments.
2. If a deployment occurred within the last 60 minutes, treat rollback as the first mitigation to attempt, per the lesson from INC-2025-047.
3. If payments-ledger-db pool utilisation is elevated, follow RB-002.
4. If NorthGate Card Switch latency is elevated, confirm the circuit breaker has tripped as expected; if not, follow RB-004.
5. If the issue correlates with a certificate expiry countdown, follow RB-003.
6. Declare an incident per POL-003 severity guidelines once customer impact is confirmed.

## Escalation
Declare SEV1 if authorisation success rate is below 70% or impact is bank-wide. Declare SEV2 for partial or regional impact. Page the payments on-call first (see the on_call_for field in employees.json for crestpay-gateway or payment-orchestrator), then engage the incident commander rotation. For third-party related degradation, engage the vendor liaison, James O'Brien for NorthGate, within 15 minutes of SEV1/SEV2 declaration.

## Rollback
For deployment-triggered incidents, roll back using the standard pipeline rollback command against the last known-good release tag. Confirm rollback completion by checking the deployed version endpoint before declaring recovery. All configuration changes to payment-orchestrator require peer review and a minimum one-hour staging soak, per the process introduced after INC-2025-047 and extended bank-wide following MTG-2026-009.
