## Summary
SEV2. On 2026-03-02 between 07:50 and 09:40 IST, customers were unable to log in to the CrestLine mobile banking app. A deployment to the mobile-banking-api authentication module introduced a regression in token validation. Approximately 31,000 customers were affected; internet banking was not impacted as it uses a separate authentication path (see ARCH-003).

## Impact
Login attempts failed with a generic "session error" message. Customers already logged in before the deployment were not affected until their session token expired. The call centre received over 1,400 calls during the window, the highest single-incident call volume recorded in 2026 to date.

## Timeline
- 07:50 - Authentication module deployment completes as part of a scheduled release.
- 07:58 - Login failure rate alert fires.
- 08:05 - Anjali Mendis identifies correlation with the recent deployment.
- 08:15 - SEV2 declared.
- 08:20 - Rollback initiated.
- 08:55 - Rollback completes; login success rate begins recovering as cached bad tokens expire.
- 09:40 - Full recovery confirmed.

## Root Cause
The deployment changed the token signature validation library version, and the new version rejected tokens signed under a legacy key format still in use for a subset of long-tenured customer accounts. This edge case was not covered in the pre-release test suite (see ARCH-003).

## Resolution
Rolled back to the previous authentication module version. A subsequent fix-forward release added explicit support for the legacy key format alongside the new library.

## Action Items
- Add legacy key format test cases to the mobile authentication regression suite (owner: Anjali Mendis) - completed 2026-03-10.
- Require a canary rollout (5% of traffic, minimum 30 minutes) for all authentication-path deployments (owner: Malith Jayawardena) - completed 2026-04-01.
- Review other services for similar legacy-format edge cases (owner: Malith Jayawardena) - in progress.

See ARCH-003 for the mobile banking platform architecture and authentication design that shaped the resolution and deployment safeguards adopted after this incident.
